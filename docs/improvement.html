How a grade is made (rubric v0, for your approval)

Every area of every strategy is checked against the same five questions. Each answer is yes, no or no evidence. Each answer must point to a test file or a record.

CheckQuestionWeight
C1Advantage. Did the current rule beat a real, tradable alternative in a point-in-time test?30
C2Untouched data. Did it hold on a period nobody looked at while designing it?20
C3Robust. Does it hold across years, nearby settings, and without its 3 best names?20
C4Risk. Are the drops and losses no worse than the alternative's (within 2 points)?20
C5Live. Do at least 20 live or paper records agree?10
  • Score = weight of yes answers ÷ weight of answered checks. "No evidence" is left out, so missing work does not count as failure.
  • N/A if C1 has no evidence, or if the answered checks carry less than half the weight. N/A areas get a measuring task, not a low grade.
  • Caps. Without a yes on C2, the best grade is C. Without a yes on C5, the best grade is B. An in-sample result can never earn an A.
  • History. A grade changes only when a check's answer changes. Every change is stored with its reason and source.
  • Review. An A area is left alone unless a new risk appears. Then it is reviewed like any other.

Where it lives

Now (stage 1). This page is on the Ledger website at improvement.html, linked from the home page. The site is public on GitHub Pages, like the Timeline and Road pages, which already show the account balance. Anyone with the link can read it. It is read-only: grades and tasks change when Claude republishes it.

Later (stages 2 and 3). Editable tasks need a database and a login. Those cannot live on GitHub Pages. They go on the box: one SQLite file and a small private server, reached through an SSH tunnel or Tailscale (a private network app). Tailscale needs your approval.

  1. Stage 1, read-only (live now). A static page on the Ledger site. Later the box rebuilds it from the rubric and the check rows every Saturday after the journal review.
  2. Stage 2, editable. Claude can only propose tasks and findings. You approve, reorder and close them on the page. Writes happen on the server, with a login.
  3. Stage 3, automatic. Test scripts and the journal write check rows. A grade recomputes when a check changes, with the reason logged.

            done_when TEXT, strategy TEXT, area INTEGER,

events     (id INTEGER PRIMARY KEY, at TEXT, who TEXT, kind TEXT, ref TEXT, note TEXT);  -- audit trail

Research files, the paper-book ledgers and the journal snapshots stay where they are. The database stores only links to them.
